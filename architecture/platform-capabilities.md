# Platform and editor capability records (v2.3, P0)

Truthful capability status only. A host, provider or editor is **not**
supported until a real conformance test passes. The machine-readable
records live in `registry/adapters.json` (generated by
`scripts/generate-registries.py`); this file is the human-readable
companion. If the two disagree, the registry wins and this file must be
regenerated/corrected.

## Capability states

| State | Meaning |
|---|---|
| `NATIVE` | The host has a documented native Skill/plugin path. |
| `PACKAGED` | Skills are delivered as a packaged folder / uploaded knowledge pack. |
| `HOST_RUNTIME` | The capability runs in the host runtime, not as a Skill install. |
| `LIMITED` | Partially applicable (e.g. interchange only, not rendering). |
| `UNSUPPORTED` | The host does not offer this path. |
| `NOT_TESTED` | No conformance test has been run here. |

**Usage vs formal conformance (P1-004):** the compatibility matrix
records Muse as VERIFIED because the knowledge-pack path is exercised
daily in this account — that is usage, not a formal conformance test.
Formal conformance stays NOT_TESTED until a CF-P0-ADAPTER-001 test
runs. The two are tracked as separate fields
(`verification_status` vs `formal_conformance_status`) in
`architecture/AGENT_COMPATIBILITY_MATRIX.yaml` and in
`registry/adapters.json`; do not read one as the other. No host
generates media itself: media execution lives only in the providers
recorded in `architecture/COMPANION_CAPABILITY_REGISTRY.yaml`
(providers section) and `registry/providers.json`.

**Muse correction (P0, F3):** the pre-P0 README table row said "Clone into
the workspace and run `bash setup.sh`" for Muse, and `docs/06` said
`setup.sh` "installs" the skills for Muse. That implied a native custom
skill install that Meta does not document. Corrected text (README +
`docs/06-installation.md`): Muse uses the repo as a versioned
knowledge pack — clone it into the workspace and read the skills from
there; `bash setup.sh` only syncs the local `.agents/skills/` copies
and (opt-in) the bundled components. No native Muse skill-install
claim is made.

## Rules

- Do not claim every host supports the same installation method.
- A provider or NLE is not "supported" until tested; until then it is
  `untested` or `planned`.
- Capability records expire when a model version, API, pricing, terms
  or feature support changes; re-probe before a production decision.
- See `registry/adapters.json` for the machine-readable records and
  `scripts/generate-registries.py` for how they are produced.
