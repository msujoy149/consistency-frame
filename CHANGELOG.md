- P0-011 exact object identity for authorization issuance (2026-11-23, branch `feat/cf-p0-safe-foundations`; corrections record `docs/implementation/CF-WO-P0-011-corrections.md`; independent-review follow-up to P0-010): the P0-010 issuance registry was a `weakref.WeakSet`, and WeakSet membership hashes the candidate and compares with `==` — so a forged subclass overriding `__eq__` (always True) and `__hash__` (the genuine object's hash) compared equal to a genuine issued context and passed the verifier with zero factory calls (reproduced: `p0-011-repro-before.txt`, `is_factory_issued(spoof): True`, `validate_private_voice_export(spoof): []`); a raising `__eq__` also made the verifier itself raise. (A) The verifier now requires the exact concrete type (`type(context) is TrustedAuthorizationContext`), and `__init_subclass__` raises `TypeError` so a subclass cannot even be defined — defence-in-depth only, never the trust anchor: the verifier rejects a subclass built by low-level construction too. (B) The registry is now a plain `dict[int, weakref.ref]` keyed by `id()`, values are weak references; verification is an int-keyed lookup followed by `target is context` — no equality or hash as an identity substitute anywhere in the registry path, so hostile `__eq__`/`__hash__` are never invoked; an `id()` lookup alone is never proof (the stored weak reference must still point at the exact object). Dead entries are removed by the weak-reference callback only when the stored value is still that exact dead ref, so a newer registration reusing the same `id()` is never removed; a stale dead entry met during verification is pruned and the check fails closed. (C) The same central verifier is used at every authorization boundary (export incl. provider-transmission approval, revocation, revocation-state); no bare `isinstance()` in any authorization-sensitive path. (D) P0-009/P0-010 preserved (immutability, separate revocation, serialization refusal, copy non-registration; revoking one identical-field context never revokes another; a forged subclass cannot revoke a genuine context or inspect its revocation status via a stolen `authorization_id`). - P0-010 factory-issuance integrity for trusted authorization contexts (2026-11-23, branch `feat/cf-p0-safe-foundations`; corrections record `docs/implementation/CF-WO-P0-010-corrections.md`; independent-review follow-up to P0-009): P0-009 made the context immutable, but immutability never proved issuance — the constructor sentinel could be imported, `__setstate__` could initialize a `__new__` object, and pickle/copy produced further objects that all passed the old `isinstance` check in `validate_private_voice_export` with zero factory calls (reproduced: `p0-010-repro-before.txt`, all five forged paths authorized).
